1 INTRODUCTION

## 1.1 OVERVIEW

The dynamic response of typical offshore wind turbine structure results from wind loading on the turbine, wind loading on the exposed part of the structure above the mean water line and wave and current loading on the submerged portion of the structure.

![](SACS2024_OpenWindPower_Fixed_Foundation/83207222f754f0b909815297a521b6c44b3e097a18d11ce36e0cdd6be1959a28.jpg)

A fully coupled analysis accounts for the interaction between all three sources of loading. For an uncoupled analysis one or more sources of loading are assumed to be independent of the others.

The SACS OpenWindPower Fixed Foundation (formerly SACS Wind Turbine) capability includes the interface to aero-elastic programs such as FAST* and GH Bladed** to conduct a fully coupled dynamic responses of a structure subjected to wave, wind and mechanical turbine loading. In addition the SACS Wind Turbine Process utility allows the user to conduct an uncoupled analysis where the wave and wind loading are generated by the SACS Wave Response modules and the mechanical loading is obtained from an external source. The wave response module uses the dynamic characteristics calculated by Dynpac and hydrodynamic properties along with wave kinematics calculated by Seastate program module.

## 1.2 PROGRAM FEATURES

The SACS GH Bladed interface uses a SACS common solution file to conduct post processing of GH Bladed results. The common solution file is generated using the GH Bladed structural description and member internal loads from GH Bladed results at given time points. The interface also has the capability

to allow the user to generate the structural model in SACS Precede which can then be converted to GH Bladed format for direct input into the GH Bladed program.

The interface is fully automated to conduct a fatigue and strength analysis of multiple time history simulations using a SACS control file generated by the GH bladed program.

The SACS-FAST interface couples the SACS Wave Response module and the FAST program allowing for full interaction between the turbine mechanical loading predicted by FAST and the wave and wind loading generated by the SACS Wave Response module. The interface uses a SACS model file for the substructure (jacket/monopile) and the wind turbine tower, Seastate input containing reference wave and wind loads, dynamic mode shape and mass files in addition to the Wave Response input file and FAST input describing the wind turbine properties. The program is designed to produce an equivalent static load file that may be solved directly to calculate the internal loads for subsequent stress analysis.

The SACS Wind Turbine Process allows the user to conduct an uncoupled wind turbine analysis where wave and wind loads are calculated by the SACS Wave Response module and the turbine force time history is obtained from a third party. The wave and wind loads can be entered either as a spectrum or a time history input. The analysis is completely automated to conduct a fatigue and strength analysis using multiple time history simulations using a user generated control file.

## 2.2 GH BLADED MODELING DEFINITION

The GH Bladed structure model definition is supplied by the SACS.IN file generated by GH Bladed.

The following information is used by the interface:

MSTART TGEOM

Header representing the geometry portion of the input file.

NTE

The integer on this line represents the number of tower members.

NTS

The integer on this line represents the number of tower nodes.

TDIAM

This line contain two values representing the member diameter (m), one value representing the diameter at each end of the member. There will be a total of NTE (number of tower members) lines.

ELSTNS

This line contains the joint number at each end of the member. There will be a total of NTE (number of tower members) lines. Each member will be referenced by the order of these lines. For example member 1 with be the first member, and member 7 will be the seventh member.

TCLOCAL

This line contains the coordinates of each joint (m). There will be a total of NTS (number of tower nodes) lines.

TZORNT

This line represents the direction cosines for local member z-axis (local member x-axis is along the member axis from end 1 to end 2). The difference between this vector and the default SACS local member z-axis will be the beta angle.

TMASS

Header representing the material portion of the input file.

WALLTHICK

This line represents the member wall thickness (m) at each end of the member. There will be a total of NTE (number of tower members) lines.

MATERIAL

This line represents the material type at each end of the member. There will be a total of NTE (number of tower members) lines.

NOMATS

The integer on this line contains the number of material types used in the model. There will be a total of NOMATS (number of material types) lines describing the different material types to follow. Each line will contain 4 entries; the material label, the material density, the modulus of elasticity, and the shear modulus.

NOTE: If the MATERIAL is different at each end of the member, the member will be divided into two separate members. The first member will contain use MATERIAL at the beginning, and the last member will use the MATERIAL at the other end. This process will add an additional joint and member.

TSTIFF

Header representing the stiffness portion of the input file.

TOWEAX

This line represents the member axial stiffness (N) (modulus of elasticity * Area). There will be a total of NTE (number of tower members) lines.

TOWGJX

This line represents the member torsional stiffness (Nm2) (Shear modulus * polar moment of inertia). There will be a total of NTE (number of tower members) lines.

TOWEIY

This line represents the member bending stiffness, Y direction (Nm2) (modulus of elasticity * Iy). There will be a total of NTE (number of tower members) lines.

TOWEIZ

This line represents the member bending stiffness, Z direction (Nm2) (modulus of elasticity * Iz). There will be a total of NTE (number of tower members) lines.

NOTE: If the TOWEAX, or TOWGJX, or TOWEIY, or TOWEIZ is different at each end of the member, the member will be divided into two separate members. The first member will contain use TOWEAX, TOWGJX, TOWEIY, and TOWEIZ at the beginning, and the last member will use TOWEAX, TOWGJX, TOWEIY, and TOWEIZ at the other end. This process will add an additional joint and member.

2.6.3 Fatigue Analysis Detailed Workflow

A partial fatigue input file contains the fatigue option lines FTOPTG and/or FTOPT2. These input lines define the SCF and S-N approaches used for the fatigue analysis. Any overrides or user defined input may also be included (see SACS Fatigue manual for further details).

NOTE: Fatigue load cases are not defined in the partial fatigue input file as these are automatically generated for a fatigue time history analysis by the automated procedure.

The fatigue analysis is conducted in three phases as described below:

2.6.3.1 PHASE 1: Generation of Sacs Common Solution file

The SACS common solution files are generated using the GH Bladed interface and stored at the location provided on the DIRECTORY line. The SACS Executive uses the information defined on the NCASES line to determine the number of simulations and therefore the number of common solution files to be generated.

2.6.3.2 PHASE 2: Generation of damage files from each simulation

Fatigue damage is calculated using the information provided on the PROB and LIFE lines in the SACS.in file.

A partial Fatigue input file is provided by the user which contains the fatigue options lines, and overrides only. The SACS Executive will update information such as the number of common solution files (in column 7) and the fatigue design life (columns 8-14) on the FTOPT line. All other information on this line entered by the user should be left untouched.

The Damage files are generated using batches of 16 common solution files. If any batch contains less than 16 common solution files then the SAC Executive will automatically calculate the number of additional post files using the information provided on the NCASES line in columns 7-7 of the FTOPT line i.e. use a value of 0- 9 for 1 to 10 common solution files, or A-F for 11 to 16 common solution files.

The Sacs executive will update the design life in columns 8-14 of the FTOPT line using the value provided on the LIFE line in the SACS.in file (convert seconds to years, for example: (6.31152e+8 sec / （$365 . 25^{ * } 24^{ * } 60^{ * } 60 ) = 20 . 0 \gamma \mathrm{ e a r s } ) .$ .

Similarly, the Executive will only change the input in column 76 of the FTOPT2 line controlling input and output of damage files. All other user input information should be left untouched. For Phase 2 this option is set to ‘O’ to output damage file only. On the generation of the last damage file in Phase 2 this option is changed to ‘I’ to input a damage file to start the damage accumulation process.

The SACS Executive will generate all FTCASE lines. The fatigue case number representing each common solution file is entered in columns 7-10 of the FTCASE line.

The number of occurrence of a particular time history is entered in column 11-20 of the FTCASE line where:

Number of occurrence =fatigue time period * 365.25*24*60*60*fraction of occurrence/duration of simulation

The fatigue time period is obtained from columns 15-21 of the FTOPT line (default is 1 year). The fraction of occurrence is obtained from PROB line in the SACS.IN file. The duration of the simulation can be calculated by multiplying the last value on the DIMENS line with the value given in the STEP line from the %25 file.

The label ‘THS’ is entered in columns 32-34 of the FTCASE line to conduct a time history fatigue analysis.

A file number is entered in columns 46-49 (numbers will be 1-16, depending upon how many additional post files are included.

2.6.3.3 PHASE 3 Accumulation of Damage.

After the generation of the last damage file the fatigue accumulation process is started automatically.

This is a linear summation of the damage contained in each damage file.

## 2.8 SUBGROUP INPUT

This is to allow for a requirement in the most recent edition of the IEC 61400-1 wind turbine design standard which specifies that for certain extreme load cases (specifically those involving turbulent wind) the characteristic load must be calculated using sub-groups. There are 2 types of sub-group:

1. The “mean” sub-group type. This requires that 6 turbulent wind seeds be simulated for each combination of external conditions and the maximum load extracted from each simulation. The characteristic load is then taken as the mean of these 6 maxima.   
2. The “half” sub-group type. This requires that 12 turbulent wind seeds be simulated for each combination of external conditions and the maximum load extracted from each simulation. The characteristic load is then taken as the mean of the top half of these 12 maxima.

The method is described in Sections 7.5 and 7.6.2 of the IEC 61400-1:2005 edition 3 design standard.

NOTE In the current implementation both GROUP and SUBGROUP inputs are not used and a maximum UC for all simulation is considered.

For a spectral input, a random surface profile is generated first subdividing the spectrum into discrete frequency bands. An AIRY wave with a random phase angle is then generated for each frequency band. The Wave Response program then reproduces the surface profile by the linear addition of AIRY waves.

The total wave kinematics are determined by adding the velocities and accelerations from the various components.

![](SACS2024_OpenWindPower_Fixed_Foundation/a03d8bff1032c06138787b466f867303c224ebc350dd94fde49657db68c60685.jpg)

When a wave spectrum is specified, the spectrum itself is analyzed and broken into Airy wave components. Only wave components with periods that are divisible into the analysis time duration are considered as possible components.

The period of a possible wave component n, is determined from the following equation:

$$T_{n} = \frac{T_{D}}{n} \quad n = 1, 2, 3 \dots n_{\max }$$

The input spectrum is divided into strips with each strip having a center frequency corresponding to the frequency of one of the possible wave components.

![](SACS2024_OpenWindPower_Fixed_Foundation/92867b8abbc06deb81e34f136adf2d95c115d358d95eba028369ba475c7514e3.jpg)

Consider the following notes about importing the time-history files:

1. If the Wave Response Analysis Time Increment (entered on the WAVTIM line) does not match the time steps in the imported files, the imported forces will be linearly interpolated.   
2. If the time histories of the imported files are shorter than the Wave Response Analysis Time, the imported time history will be padded by the force values at the last time step.   
3. If the time histories of the imported files are longer than the Wave Response analysis time, the extra time steps will be ignored.   
4. If the imported history starts at the non-zero time, the imported time history will be padded by the force values at the first step between the time zero and the imported history starting time.5. The force time-history file types entered on THLOAD lines must conform to the file types selected in the SACS Analysis Generator. Otherwise, the Wave Response returns error messages.

## 4.3 DYNAMIC SUPER ELEMENT

The jacket structure can also be reduced to a dynamic super element using the SACS Dynamic Superelement module. The module allows the generation of a dynamic superelement based upon the Craig-Brampton approach. The generation of a dynamic superelement and the corresponding reduced load vector is a three step process. The first step is to run the SACS Dynpac module to produce mass, mode, the dynamic superelement data and transformation files. Next, the SACS Wave Response module is used to generate the dynamic superelement force file. Lastly, the SACS Dynamic Superelement module is used to generate the reduced stiffness, mass, damping and load vector.

NOTE: The wave response run can be omitted if the load vector is not required.

## 5.3 ACCUMULATION OF DAMAGE

The accumulation of damage phase needs to sum up the damage from all the common solution files (CSF’s). As mentioned above it happens in two stages. Firstly, the damage of 16 CSF’s is summed up in one run. Similar fatigue runs of 16 CSF summations are run in parallel (based on number of cores available). Thus for 100 CSF’s, there will be 6 such runs. Finally, the last run will sum up the damage calculated in these 6 runs (for 100 CSF case) and add it to the damage from the remaining 4 CSF’s

This verification is undertaken by using multiple copies of a single CSF file. Thus if we make 100 such copies, then the damage should be 100 times the damage of a single CSF file. For this verification, the CSF file chosen is the file used for validation of Phase 2. Thus we know that the damage for the single CSF is accurate.

A sample GH bladed process run was created with 100 cases. It can be seen that the fatigue damage (see listing file transcript below) for each run is 16 times the damage calculated in Phase 2. This is verified for all the runs in Folders 1 through 6.
